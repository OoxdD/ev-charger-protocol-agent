# 充电订单智能分析工具 — 工作记录（客户版）

**整理日期：** 2026年7月29日  
**项目名称：** 充电桩协议 / 订单日志智能分析助手  
**使用方式：** 打开网页，上传充电日志（txt），即可生成中文分析报告  

---

## 一、我们一起在做什么

平台侧经常需要根据**充电桩上报日志、平台业务报文**，快速判断一笔订单是否正常：有没有真正启动成功、为何停止、电量费用是否合理、有没有告警或故障。

以往这类排查往往要人工翻很长的日志、对照协议文档。  
我们一起做的是：把这些经验规则做成**可视化分析工具**，上传日志后自动出结论，方便客服、运维、现场技术同事使用。

当前可在本机网页使用，默认地址：`http://本机IP:6894/`

## 二、已完成的主要能力（按业务场景）

### 1. 支持多种协议与日志

| 内容 | 说明 |
|------|------|
| 云快充协议 | 已按平台协议 **V1.7** 解析；字段用中文展示，并带单位 |
| 微鲸协议 | 已接入，可解析相关报文 |
| 万马协议 | 已接入，处理粘连报文、VIN 启动等常见情况 |
| 平台业务日志 | 支持上传平台侧 txt（含 JSON 业务数据），与设备侧信息互相印证 |

**效果：** 不再只能看“某一帧十六进制”，而是尽量还原成**一整笔订单**来分析。

---

### 2. 一桩多枪、多订单也能分得清

充电站经常是一桩多枪、同一时间多笔订单。我们做了：

- 可按**订单号 / 流水号**筛选具体哪一单  
- 若日志里发现多笔订单，先列出清单，再选中一单分析  

**效果：** 避免把 A 枪的订单和 B 枪的订单混在一起。

---

### 3. 启动是否成功 — 自动判断

结合远程启动指令、启动应答、枪口状态、过程中的电流/电压/电量等，判断：

- 远程启动是否成功  
- 是否出现“启动失败”（例如枪被占用、未插枪等），并直接给出失败原因文案  
- **启动失败类订单**：结论为明确失败，**无需再人工复核是否“假成功”**

---

### 4. 为什么停止 — 自动分类

按日志特征区分常见停止类型，例如：

| 类型 | 典型情况 |
|------|----------|
| 用户远程停止 | 平台下发远程停止；若无具体停止原因文案，按用户远程停止处理 |
| 设备 / 拔枪停止 | 无远程停止指令，结合设备结束原因与枪口状态变化 |
| 疑似急停 | 枪口短暂故障态，但没有配套告警信息时，提示需人工确认 |
| 枪口故障 | 有故障态，且伴随告警信息，提示到设备侧排查 |
| 离线相关故障 | 先离线再出现故障态时，按离线场景归类，避免误判成急停 |

**效果：** 报告里直接给出“停止类型 + 停止原因说明”，减少翻日志时间。

---

### 5. 电量、费用、分时是否合理

报告会汇总并校验：

- 实际充电电量、尖峰平谷分时电量  
- 电费、服务费、占位费、费用合计  
- 过程上报电量 与 账单电量 是否一致  
- 用「平均功率 × 充电时间」估算电量，核对是否大致合理  
- 展示需求电压、需求电流（车辆侧要求）等过程数据  

另已处理一类误报：起止表码都为 0 时，不再错误提示“表码不一致”。

---

### 6. 充电时长怎么算（重要修正）

**问题（已发现并修正）：**  
有的订单结束很晚，中间枪口已变成“占位”（OCCUPYING），车其实已不在充电，但若按订单起止时间算，会把占位时间也算进“充电时长”，显得偏长。

**正确规则（已按此修改）：**  
**只累计枪口处于“充电中（CHARGING）”的时间**；一旦变成占位等状态，就不再计入充电时长。

**举例：** 某单订单起止约 66 分钟，其中大量为占位；按充电状态累计后，实际充电约 **14 分钟**，与电量更匹配。

---

### 7. 告警与异常提示

- 日志中有告警信息时，报告中摘录展示  
- 出现异常时，结论中提示：**到设备侧核对实际数据与协议表现**  
- 减少容易误导的“疑似异常”类表述，让结论更清晰  

---

### 8. 界面与使用体验

- 提供可视化网页：上传日志 → 出中文结论 + 字段明细  
- 结论按条目展示（启动、停止、费用、占位、分时等），便于直接转发或留档  
- 服务默认端口调整为 **6894**，便于本机对外提供分析服务

## 四、使用方式（给业务同事）

1. 打开分析网页（本机服务地址，端口 6894）  
2. 上传平台导出的充电订单日志（txt）  
3. 如有多笔订单，按提示选择订单号 / 流水号  
4. 查看报告：结论条目 + 详细字段  
5. 需要时把结论转发研发 / 现场，到设备侧进一步核对
